# ISSUE (open first at https://github.com/e2nIEE/pandapipes/issues/new)

**Title:** Optional local-LLM explanations for pandapipes errors (`pandapipes.explain`)

**Body:**

### Motivation
Errors such as `PipeflowNotConverged` are hard to interpret for new users. The new
`pandapipes.diagnostic` framework finds likely causes, but the user still has to
read and interpret its output.

### Proposal
An optional, opt-in package `pandapipes.explain` that, when a pandapipes call fails,
prints a short plain-English explanation (cause, evidence, minimal fix) generated by a
**locally running** Ollama model. It combines the traceback, network statistics, selected
checks from `pandapipes.diagnostic`, and a small curated knowledge base.

- Off by default; enabled with `pandapipes.explain.enable()` or a `with explain():` block
- No new required dependencies (Ollama is reached over `urllib`)
- No network calls beyond `localhost`; no telemetry
- If Ollama is unavailable, the original error is shown unchanged
- Tests are CI-safe (LLM mocked); real-model tests are opt-in

I have an implementation ready and would open a PR against `develop` if this is of interest.

# PULL REQUEST (base: e2nIEE/pandapipes `develop`, compare: AfaqJ:feature/explain-diagnostic-layer)

**Title:** Add pandapipes.explain: optional local-LLM error explanations for new users

**Body:**

Closes #<ISSUE NUMBER>

## What
An optional add-on layer that helps new users understand why a pandapipes simulation failed.
Built in collaboration with Professor Marten Klein (BTU Cottbus-Senftenberg) to make onboarding easier.

When a pandapipes call raises (non-convergence, invalid values, topology or runtime errors), the
normal stack trace is printed as usual and, below it, a local LLM explains in plain English what
most likely went wrong, the evidence from the network, and a minimal fix.

## Usage (two extra lines)
```bash
ollama pull llama3.1:8b        # one-time: install a model of your choice
```
```python
import pandapipes.explain
pandapipes.explain.enable()    # rest of your script is unchanged
```
or scoped: `with pandapipes.explain.explain(): pp.pipeflow(net)`

## Safe to add
- **Completely optional / opt-in** - nothing changes unless `enable()` is called
- **Never interferes**: the original exception and traceback are untouched; the explanation is printed after it
- **Skips itself if Ollama is not installed or not running** (prints a short hint, nothing else)
- **No new required dependencies** (the `explain` extra is empty; Ollama is reached over `urllib`)
- **No network calls beyond localhost**, no telemetry, no API keys - user data never leaves the machine
- Builds on `pandapipes.diagnostic`: runs relevant checks and feeds the findings to the model; a test fails if an imported check is renamed or removed

## Tests / CI
- `src/pandapipes/test/explain/`: CI-safe, LLM fully mocked, no Ollama needed
- Real-model integration tests are opt-in (`PANDAPIPES_EXPLAIN_RUN_OLLAMA=1`)
- Full suite passes locally; CI green on my fork (Linux + Windows, Python 3.10-3.13, with and without numba, lint, docs)

## Docs
`src/pandapipes/explain/README.md` covers install, model choice, privacy, troubleshooting, and an architecture section for maintainers. CHANGELOG entry added.
